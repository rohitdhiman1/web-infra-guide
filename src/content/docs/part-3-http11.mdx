HTTP/1.1 is plain text, so you can read and write it by hand. Learn it at this level and HTTP/2 and HTTP/3 become "the same meaning, different framing." Plan about two weeks. The reference is RFC 9110 (semantics) and RFC 9112 (HTTP/1.1 framing).

## Concepts

<span id="concept-3-1"></span>

### <span class="concept-badge">3.1</span> Message structure

A request line (`GET /path HTTP/1.1`), headers, an empty line (`\r\n\r\n`), then an optional body. Responses swap the first line for a status line.

<span id="concept-3-2"></span>

### <span class="concept-badge">3.2</span> Methods and their properties

GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS. Know which are *safe* (no side effects) and *idempotent* (safe to retry). Proxies decide whether to retry based on this.

<span id="concept-3-3"></span>

### <span class="concept-badge">3.3</span> Status codes

1xx informational, 2xx success, 3xx redirect, 4xx client error, 5xx server error. Know these cold: 200, 201, 204, 301, 302, 304, 307, 308, 400, 401, 403, 404, 405, 413, 429, 499 (nginx-specific: client closed), 500, 502, 503, 504.

<span id="concept-3-4"></span>

### <span class="concept-badge">3.4</span> 502 vs 503 vs 504

502: the upstream gave a bad or no response. 503: the service is unavailable or overloaded. 504: the upstream was too slow. This distinction is the single most useful debugging skill behind a proxy.

<span id="concept-3-5"></span>

### <span class="concept-badge">3.5</span> The Host header

Mandatory in HTTP/1.1. It lets one IP serve many sites (virtual hosting) and drives nginx's `server_name` matching.

<span id="concept-3-6"></span>

### <span class="concept-badge">3.6</span> Message length

A body ends via `Content-Length`, via `Transfer-Encoding: chunked`, or by closing the connection. Getting this wrong causes hangs and request smuggling attacks.

<span id="concept-3-7"></span>

### <span class="concept-badge">3.7</span> Chunked transfer encoding

Each chunk is its size in hex, then the data; a zero-size chunk ends it. Used for streaming when the total size is unknown.

<span id="concept-3-8"></span>

### <span class="concept-badge">3.8</span> Persistent connections (keep-alive)

HTTP/1.1 reuses connections by default. `Connection: close` ends them. One connection still handles only one request at a time.

<span id="concept-3-9"></span>

### <span class="concept-badge">3.9</span> Head-of-line blocking

Because of [3.8](#concept-3-8), a slow response blocks everything queued behind it on that connection. Browsers open about 6 connections per host to work around it.

<span id="concept-3-10"></span>

### <span class="concept-badge">3.10</span> Content negotiation and compression

`Accept`, `Accept-Encoding`, `Content-Type`, `Content-Encoding`. gzip and brotli shrink text responses a lot.

<span id="concept-3-11"></span>

### <span class="concept-badge">3.11</span> Caching

`Cache-Control` (max-age, no-cache, no-store, private, public, s-maxage), `ETag` and `If-None-Match`, `Last-Modified` and `If-Modified-Since`, and the 304 Not Modified response. `Vary` tells caches which request headers change the response.

<span id="concept-3-12"></span>

### <span class="concept-badge">3.12</span> Redirects

301 and 308 are permanent; 302 and 307 are temporary. 307 and 308 keep the method and body, which matters for POST.

<span id="concept-3-13"></span>

### <span class="concept-badge">3.13</span> Range requests

`Range: bytes=0-1023` and the 206 Partial Content response. This powers resumable downloads and video seeking.

<span id="concept-3-14"></span>

### <span class="concept-badge">3.14</span> Cookies and state

`Set-Cookie` with attributes Secure, HttpOnly, SameSite, Domain, Path. HTTP is stateless; cookies are how sessions are layered on top.

<span id="concept-3-15"></span>

### <span class="concept-badge">3.15</span> CORS

Browsers block cross-origin reads unless the server says otherwise via `Access-Control-Allow-*` headers. Learn the preflight OPTIONS request.

<span id="concept-3-16"></span>

### <span class="concept-badge">3.16</span> Forwarding headers

`X-Forwarded-For`, `X-Forwarded-Proto`, `X-Real-IP` and the standard `Forwarded` header. Behind a proxy, the app only learns the real client this way.

## In the sandbox

1. Talk HTTP by hand: `nc example.com 80`, then type `GET / HTTP/1.1`, `Host: example.com` and an empty line.
2. Use `curl -v` and `curl -I` against real sites. Read every header and look up any you don't know.
3. Fetch a page twice with `curl -H 'If-None-Match: "<etag>"'` and get a 304.
4. Run `curl -r 0-99` for a range request and check the 206.
5. Open your browser's DevTools Network tab on a big site. Inspect caching headers, cookies and the protocol column.
